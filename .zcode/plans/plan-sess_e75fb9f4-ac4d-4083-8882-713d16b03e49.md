## Rencana: Aplikasi Web "Daftar Tugas" (todo/)

Konteks: folder `todo/` belum ada; yang ada entri placeholder `soon: true` di `js/apps.js`. Aplikasi akan dibuat mengikuti pola aplikasi Catatan (single-file, vanilla JS).

### File yang dibuat/diubah
1. **`todo/index.html`** (baru, single-file: HTML + CSS + JS) dengan fitur:
   - **Dasar**: tambah tugas (judul + catatan opsional), centang selesai, edit inline, hapus (dengan konfirmasi).
   - **Filter status**: tab Semua / Belum selesai / Selesai + hitungan tiap tab; tombol "Hapus semua tugas selesai".
   - **Prioritas**: rendah/sedang/tinggi (warna badge); tugas prioritas tinggi diurutkan di atas; **pencarian** teks pada judul/catatan.
   - **Tenggat (deadline)**: input tanggal; tugas lewat tenggat & belum selesai ditandai merah "Terlambat", diurutkan di atas.
   - **Storage ganda** meniru `catatan/index.html`:
     - Default: `localStorage` kunci `"todo"`.
     - Mode Supabase: REST endpoint `PROJECT_URL/rest/v1/todos` + **Supabase Auth** (login/signup email-password, refresh token, sesi di `localStorage` kunci `"todo_sesi"`), overlay login, translasi pesan error ke Indonesia. Skema tabel `todos` (kolom: id uuid, user_id, judul, catatan, selesai bool, prioritas, tenggat date, created_at) dengan RLS per-user — SQL-nya diberikan dalam banner setup di dalam aplikasi (cara yang sama seperti Catatan).
   - UI: CSS variables, dark mode otomatis (`prefers-color-scheme`), responsif mobile, link "← Beranda", badge "Segera hadir" hilang otomatis.
2. **`js/apps.js`**: ubah `todo.soon: true → false`.

### Yang TIDAK dilakukan
- Tidak ada testing/otomasi — pengujian manual dilakukan user. Di akhir saya akan menyampaikan daftar poin pengujian manual beserta indikator keberhasilannya.

- Konfigurasi Supabase (URL + anon key) akan dipakai sama dengan yang sudah terisi di `catatan/index.html`; user tetap perlu menjalankan SQL pembuatan tabel `todos` di Supabase (disediakan di banner setup dalam aplikasi).
